# Spec Draft: JSC-101

## Source
- Issue Key: JSC-101
- Title: Skip the static coverage data when version.json does not exis
- Description:
Currently, `version.json` does not exist, so we use the default value.

## Goal
Skip static coverage data when `version.json` does not exist.

## In Scope
- Change the Java CLI version-manifest reader so a missing `version.json` no longer uses a default schema version. (inferred)
- Skip the entire static-coverage session when its `version.json` is missing, unreadable, malformed, or declares an unsupported schema version. (inferred)
- Preserve processing of other valid static-coverage sessions. (inferred)

## Out of Scope
- Not explicitly defined in Jira.

## Behavior
- The Java CLI reads a `version.json` manifest before it processes a static-coverage session. (inferred)
- A missing, unreadable, malformed, or unsupported manifest rejects and skips that entire session. (inferred)
- The missing-file case no longer proceeds by using a default value. (inferred)
- Other valid sessions continue to be processed. (inferred)
- If every session is skipped, the CLI retains its existing no-static-coverage-data failure behavior. (inferred)

## Edge Cases (Optional)
- A `version.json` path that is absent at processing time is handled without substituting a default value. (inferred)
- A manifest that cannot be read, cannot be parsed as the required JSON object, or declares an unsupported schema version is skipped under the same session-level policy. (inferred)

## Done When (Acceptance Criteria)
- [ ] A session with no `version.json` is skipped and does not use a default schema version. (inferred)
- [ ] Sessions with unreadable, malformed, or unsupported `version.json` manifests are also skipped. (inferred)
- [ ] A valid session is still processed when another session is skipped. (inferred)
- [ ] When all sessions are skipped, the existing no-static-coverage-data failure is retained. (inferred)
- [ ] Automated tests cover the missing-manifest behavior and its interaction with valid sessions. (inferred)

## Clarifications

### Assumptions
- [A1] “Static coverage data” refers to the data currently generated after the default value is selected for a missing `version.json` → **Resolved:** It means the entire static-coverage session.

### Unclear Points
- [U1] Jira does not define which component owns the `version.json` lookup or the precise unit of data that must be skipped → **Resolved:** The Java CLI version-manifest reader and parser own this behavior, and the parser skips the entire session.

### Missing Info
- [M1] Jira does not state the expected behavior for an unreadable or malformed `version.json`, nor whether it should match the missing-file behavior → **Resolved:** Missing, unreadable, malformed, and unsupported manifests all skip the entire session.

### Questions for Human
- [Q1] (re [A1]) Does “skip the static coverage data” mean omit the entire static-coverage result, or only the portion associated with the version lookup? → **Answered:** Omit the entire static-coverage session.
- [Q2] (re [U1]) Which component and code path is expected to detect a missing `version.json`? → **Answered:** The Java CLI version-manifest reader and parser.
- [Q3] (re [M1]) Should unreadable or malformed `version.json` inputs also skip static coverage data, or retain their current behavior? → **Answered:** They skip the entire session, as does an unsupported manifest.

### Risks
- [R1] (re [U1]) An implementation in the wrong layer could suppress unrelated coverage data or leave the default-value path active. This is mitigated by keeping validation in the manifest reader and session handling in the parser.
