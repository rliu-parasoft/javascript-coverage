# Spec Draft: JSC-112

## Source

- Issue Key: JSC-112
- Title: Add a version.json file when creating the runtime path.
- Description: Create `version.json` beneath the path supplied by `--jscov.agent.runtimeData`. Its content must include `schemaVersion` set to `1.0` and `toolVersion` set to the jscov-agent version.

## Goal

At agent initialization, create or refresh a `version.json` file in the agent runtime-data path containing the schema version and the installed jscov-agent version.

## In Scope

- Add an isolated runtime-data metadata writer that is constructed during agent initialization.
- Create or overwrite `version.json` directly under the path specified by `--jscov.agent.runtimeData` on every agent initialization.
- Write a JSON object with `schemaVersion: "1.0"` and `toolVersion` equal to the jscov-agent package version.
- Write any metadata creation or write failure to the initialized agent log file and emit its localized error message through the agent console logger, then stop agent initialization without making the failure fatal to the preload module.
- Test file creation, replacement, content, package-version sourcing, and non-blocking write-failure logging.

## Out of Scope

Not explicitly defined in Jira.

## Behavior

- During agent initialization, construct the runtime-data metadata writer after runtime-data configuration is resolved.
- The writer replaces `<runtimeData>/version.json` on every initialization, including when the runtime-data directory and file already exist.
- The file contains `{"schemaVersion":"1.0","toolVersion":"<jscov-agent package version>"}`.
- If metadata creation or writing fails after logging is initialized, write the error to the agent log file, emit its localized error message to the command line, stop agent initialization, and do not throw from the preload module.
- The file log retains the error stack trace. The console output contains the error message without a stack trace.

## Edge Cases (Optional)

- A metadata write failure is logged as a non-blocking runtime-data initialization error; the command line receives its localized error message without a stack trace.

## Done When (Acceptance Criteria)

- [ ] The agent initializes a runtime-data metadata writer after resolving `--jscov.agent.runtimeData`.
- [ ] A runtime-data path configured through `--jscov.agent.runtimeData` contains `version.json` after initialization.
- [ ] An existing `version.json` is replaced on each agent initialization.
- [ ] The file is valid JSON with `schemaVersion` equal to `"1.0"`.
- [ ] The `toolVersion` value equals the jscov-agent package version.
- [ ] A failure writing `version.json`, including a symbolic-link manifest, is written to the agent log file, emits its localized error message to the command line without a stack trace, and stops agent initialization without throwing from the preload module.
- [ ] A manifest failure log contains one localized summary and a distinct specific error in its stack trace, without duplicate message text.

## Clarifications

### Assumptions

- [A1] `version.json` is created only as part of creating the runtime-data directory, matching the Jira title. → **Resolved:** Initialize and overwrite the file on every agent initialization, whether or not the directory already exists.

### Unclear Points

- [U1] It is unclear whether `version.json` should be replaced, preserved, or validated when it already exists. → **Resolved:** Replace it on every agent initialization.

### Missing Info

- [M1] The issue does not state what should happen when the runtime-data directory cannot be created or written. → **Resolved:** Existing runtime-data directory validation remains unchanged; after logger initialization, every `version.json` creation or write failure is recorded in the agent log file, emits its localized error message to the command line without a stack trace, and stops agent initialization without failing the preload module.

### Questions for Human

- [Q1] (re [A1]) Should the file also be created or refreshed when the configured runtime-data directory already exists? → **Answered:** Refresh it on every agent initialization.
- [Q2] (re [U1]) If `version.json` already exists, should the agent overwrite it with current metadata, preserve it, or fail? → **Answered:** Overwrite it.
- [Q3] (re [M1]) Should an I/O failure creating or writing this metadata abort agent initialization, or be reported and allow initialization to continue? → **Answered:** Record the error in the agent log file, emit its localized error message to the command line without a stack trace, and stop agent initialization without making the failure fatal to the preload module.

### Risks

- [R1] (re [U1]) Unspecified overwrite behavior could leave stale tool metadata or unexpectedly replace user-managed content. → **Mitigated:** Intentional replacement on every initialization keeps metadata current.
