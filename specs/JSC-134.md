# Specification: JSC-134

## Source

- Issue Key: JSC-134
- Title: Collect static coverage for jscov-agent
- Description:
  - Add the following script to `package.json`: `"build:instrument": "vite build --mode instrument"`.
  - When Vite runs in instrument mode, use `vite-plugin-istanbul` for instrumentation.
  - Introduce `parasoft-istanbul-lib-instrument-6.0.3-1.tgz` to override the original `istanbul-lib-instrument`.
  - Create the Jenkins job `javascript.coverage.coverage-for-javascript`:
    - Download `parasoft_javascript_coverage_1.0.0.zip` from the nightly-build distribution.
    - Use the latest `parasoft-istanbul-lib-instrument-6.0.3-1.tgz`.
    - Run `npm run build:instrument` to generate static-coverage JSON files.
    - Use the latest `parasoft-jscov.jar` to generate the static-coverage XML report and upload it to DTP.
  - To upload coverage to DTP:
    - Keep Java and JavaScript coverage data separate in DTP.
    - Use a session ID different from the Java-coverage session ID.
    - Associate the session ID with the existing `JavascriptCoverageAgent` filter.

## Goal

Enable a Vite-based build for `jscov-agent` that emits static-coverage snapshots and define the corresponding Jenkins/DTP reporting flow.

## In Scope

- Add an instrumented Vite build command to the affected `jscov-agent` package.
- Configure the local Parasoft Vite plugin for instrumentation in instrument mode.
- Resolve the direct `istanbul-lib-instrument` dependency to the supplied Parasoft package.
- Define Jenkins automation that builds instrumented assets, creates a static-coverage XML report, and uploads it to DTP.
- Keep the JavaScript upload separate from Java coverage by using a distinct session ID associated with the `JavascriptCoverageAgent` filter.

## Out of Scope

Not explicitly defined in Jira.

## Behavior

- `npm run build:instrument` invokes `vite build --mode instrument` in the affected package.
- The instrument-mode Vite build uses the local Parasoft Vite plugin, which directly instruments the SSR agent source.
- The instrumented build resolves the SSR source directory relative to `vite.config.ts`, not the invoking process's working directory. (inferred)
- The instrumented build produces static-coverage JSON snapshots that `parasoft-jscov.jar` can convert to a static-coverage XML report. (inferred)
- Jenkins obtains the current JavaScript Coverage distribution for `parasoft-jscov.jar` and the Parasoft instrumentation package before running the instrumented build.
- Jenkins uploads the generated JavaScript static-coverage XML report to DTP under the configured `DTP_SESSION_TAG`, which must be distinct from Java coverage. (inferred)
- Jenkins resolves the DTP username and password from the `DTP_CREDENTIAL_ID` Username with password credential parameter for every report-generation run, because `parasoft-jscov.jar` requires them even when publication is disabled. (inferred)

## Edge Cases (Optional)

- The instrumented build must not replace the package's ordinary build behavior. (inferred)
- If the generated snapshots are invalid or absent, the report-generation step must not upload misleading coverage data. (inferred)

## Corrections and Additions

### Corrections

- The Vite target is `integration/jscov-agent`, which contains `package.json` and `vite.config.ts`.
- Create a dedicated Jenkins pipeline file named `jenkins/javascript-coverage.jenkinsfile` for the job `javascript.coverage.coverage-for-javascript`.
- The pipeline implements static coverage now and is structured to incorporate runtime coverage in a later change.
- `vite-plugin-istanbul` is redundant for this SSR-only build because it skips SSR transforms. The local Parasoft Vite plugin directly invokes the vendored `istanbul-lib-instrument` dependency and is the sole instrument-mode plugin.
- Declare the vendored Parasoft archive as the direct `istanbul-lib-instrument` dependency. No npm override is needed because no remaining transitive dependency resolves that package.
- Keep this repository's existing Jenkins and package-manager conventions rather than adopting the supplied SignalTest pipeline's build approach.
- Keep the versioned Parasoft instrumentation archive under `integration/jscov-agent/vendor/` and commit the package lockfile for local development. Jenkins overwrites that archive with the nightly artifact and installs it without using the lockfile, because regenerated archives can have different bytes while retaining the same version metadata.

### Additions

- The ordinary build is preserved and invalid or absent snapshots prevent a misleading upload.
- Automated coverage is included as an inferred acceptance criterion.
- The instrumented-build regression runs with a temporary working directory and verifies that configuration-relative source resolution still generates static-coverage snapshots.
